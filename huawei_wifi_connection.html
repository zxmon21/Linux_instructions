Huawei SUN2000 WiFi (AP Mode) Setup on Ubuntu

  1. Install required tools 
    sudo apt update
sudo apt install network-manager netcat-openbsd
  2. Identify your WiFi interface 
    nmcli device status

    Look for something like wlp2s0 (USB WiFi adapter).

  3. Scan for Huawei inverter WiFi 
    nmcli device wifi list

    Look for SSID like SUN2000-HV2290249916.

    1. Create a password file for WiFi authentication 
      nano ~/sun2000_passwd.conf

      Add the WiFi PSK (Huawei default is often Changeme unless changed): 

    2. 802-11-wireless-security.psk:Changeme

    3. Secure the file:

      chmod 600 ~/sun2000_passwd.conf
  5. Create WiFi connection profile with WPA2 security (single step) 
    sudo nmcli connection add \
type wifi \
ifname wlp2s0 \
con-name sun2000 \
ssid "SUN2000-HV2290249916" \
wifi-sec.key-mgmt wpa-psk
sudo nmcli connection modify sun2000 \
ipv4.method manual \
ipv4.addresses 192.168.200.2/24 \
ipv4.gateway 192.168.200.1 \
ipv4.dns 192.168.200.1
  6. Activate connection using passwd-file 
    sudo nmcli connection up sun2000 \
passwd-file ~/sun2000_passwd.conf
  7. Verify IP configuration 
    nmcli device show wlp2s0
ip route

    You should see:
    192.168.200.2/24 and route to 192.168.200.0/24

  8. Test Modbus connectivity 
    nc -zv 192.168.200.1 6607

    If successful, the inverter is reachable.

    1. Create WiFi recovery script 
      nano ~/restore_sun.sh

    2. Paste:

      #!/bin/bash

IF="wlp2s0"
SSID="SUN2000-HV2290249916"

nmcli device disconnect "$IF" 2>/dev/null
pkill -f "dhclient.*$IF" 2>/dev/null

ip link set "$IF" down
sleep 3
ip link set "$IF" up
sleep 5

nmcli device wifi connect "$SSID" ifname "$IF"
  10. Make script executable 
    chmod +x ~/restore_sun.sh
  11. Create watchdog script 
    nano ~/sun_watchdog.sh

    Paste:

    #!/bin/bash

if ! nc -z -w3 192.168.200.1 6607; then
    ~/restore_sun.sh
fi
  12. Make watchdog executable 
    chmod +x ~/sun_watchdog.sh
  13. Run watchdog automatically (cron) 
    crontab -e

    Add:

    */2 * * * * /home/$USER/sun_watchdog.sh
  14. Verify everything works 
    nc -zv 192.168.200.1 6607
nmcli device status

    If WiFi drops, it should recover automatically within ~2 minutes.

  15. Route Home Assistant VM traffic to the inverter (host-side DNAT)

    Home Assistant OS (bridged on br0, e.g. 192.168.50.x) can't add custom routes to reach the inverter's separate WiFi network. Instead, forward a port on the host (192.168.50.12) through to the inverter via wlp2s0.

    Edit the ufw rules file:

    sudo nano /etc/ufw/before.rules

    Add a *nat section near the top of the file, before *filter (create it if it doesn't already exist): 

    *nat
:PREROUTING ACCEPT [0:0]
:POSTROUTING ACCEPT [0:0]
-A PREROUTING -i br0 -p tcp --dport 6607 -d 192.168.50.12 -j DNAT --to-destination 192.168.200.1:6607
-A POSTROUTING -o wlp2s0 -d 192.168.200.1 -j MASQUERADE
COMMIT

    (192.168.50.12 = host's br0 IP, 192.168.200.1 = inverter, 6607 = Huawei Solar Modbus port)

  16. Reload ufw so the rules load and persist across reboots 
    sudo ufw disable
sudo ufw enable
  17. Verify the NAT rules are active 
    sudo iptables -t nat -L PREROUTING -n -v
sudo iptables -t nat -L POSTROUTING -n -v
  18. Point the Huawei Solar integration at the host, not the inverter

    In Home Assistant, configure the Huawei Solar integration to connect to the host's br0 address instead of the inverter's real address: 

    192.168.50.12 : 6607
  19. Test reachability from Home Assistant 
    nc -zv -w3 192.168.50.12 6607

    Should report open.

  20. Notes

    - Huawei SUN2000 WiFi AP mode is unstable for long-term use
    - Static IP improves reliability significantly
    - Ethernet or WiFi client mode is more stable if available
